pyLogi Help

pyLogi manages Logitech mice, keyboards and webcams over USB, Bluetooth and the Unifying, Bolt and LIGHTSPEED receivers. It talks to the devices directly (HID++), so you do not need any Logitech software.

To keep a copy on paper, press Save as PDF… (bottom left of this window) or run pylogi --export-help manual.pdf.

Getting started

  1. Connect your devices. Plug in the receiver, connect the cable or pair over Bluetooth. Wireless devices that are asleep show as Offline; move the mouse or press a key to wake them.
  2. First start. pyLogi asks once whether it may download product photos (see Settings). Nothing is downloaded before you answer.
  3. Open a device by clicking its card. Changes are applied immediately; there is no Save button except for the onboard profiles.
  4. If nothing is listed, see Troubleshooting: on Linux your user needs permission to open /dev/hidraw*.

Only one program should manage a device at a time. If another one (OpenLogi, Solaar, logiops, Logi Options+, G HUB) is running, a yellow banner warns you, because both programs would overwrite each other's button settings.

The Devices screen

The header shows the number of devices and these controls:

  • Grid / List / By category (three buttons): how devices are shown. The choice is remembered. By category groups them into mice, keyboards, webcams and others.
  • Settings: language, appearance, photos and more (see Settings).
  • Add: pair new devices (see Adding and removing devices).
  • ?: this help, the About dialog and the licence.

Cards. Each card shows the product photo, the name and a category label. Top left: how the device is connected (receiver logo and slot number, Bluetooth or a plug for USB; an empty circle means offline). Top right: the battery level. A red border means the device is offline.

The … menu of a card offers: Open, Rescan (reads the devices again right now), Choose picture… (use your own image), Use the original picture and Remove….

Receivers are not listed as devices; they are managed from Add. Cards can be reached with Tab and opened with Enter or Space.

The device page

A top bar shows the name, battery and connection state, with a back button. The left sidebar lists the sections available for that device; only sections the device supports appear: Buttons (mice), Pointer, Profiles, Lighting, Camera and always Device. Sections load in the background and show Loading… for a moment, so the window never freezes.

Buttons and actions (mice)

The mouse photo shows a dot and a card for each programmable button. Click a card (or its dot) to edit it in the Button inspector on the right. The Action list offers:

Original functionThe button keeps doing what the mouse firmware does.
Another buttonThe button behaves like a different button of the same mouse. Done inside the mouse.
Keyboard shortcutCtrl / Shift / Alt / Win switches plus a key. The keys are pressed when you press the button and released when you release it.
Media keyPlay/Pause, next/previous track, volume, mute, calculator, mail, browser keys… Sent once per press.
Mouse clickLeft, right, middle, back or forward click (held while the button is held).
ScrollOne scroll step up, down, left or right per press.
Type textTypes the text when you press the button. It assumes a US keyboard layout; punctuation can differ on other layouts.
Run commandStarts a program with its arguments. It does not use a shell, so pipes, ; and variables are not interpreted.
Change DPINext or previous DPI step.
MacroA sequence of steps, one per line: key ctrl+shift+T, text hello, media Play/Pause, click left, scroll down, run firefox and wait 250 (milliseconds). A number and x in front repeats a step (3x scroll down); lines starting with # are comments. A script with an error is not saved: the line is shown under the editor. The same macro cannot overlap itself, and closing pyLogi stops it.
GestureHold the button and move the mouse: when you release it, the direction (up, down, left, right) runs its macro, and a click with almost no movement runs the Click macro. Movement needed sets how far the mouse must travel. The pointer does not move while the button is held. Written from the documented protocol; not yet verified on every mouse.
DisabledThe button does nothing.

All actions except Original function and Another button are performed by pyLogi, so pyLogi must be running (it can sit in the tray). Those buttons are diverted to the software while pyLogi runs and are given back when you disable management or remove the device. On Linux the keys are sent through a virtual input device (/dev/uinput).

Profiles per application. The strip above the mouse has the Default profile and one tab per application. + Add application creates a profile named after the application's window class (for example firefox; the current one is suggested). An application profile only needs the buttons that differ: the others are inherited from Default, and choosing Original function in an application profile switches a button back to normal there. Right-click a tab to delete it. Active shows which profile is in force. Switching follows the window in focus automatically on X11 and, on Wayland, through the helper extension on GNOME (pylogi --install-gnome-extension, then log out and in) or the compositor's own tool on Sway (swaymsg), Hyprland (hyprctl), Niri (niri) and KDE Plasma (kdotool). Without any of them, only the Default profile applies.

Button settings are remembered and written again every time the device reconnects, because mice forget them when they power off.

Pointer, wheel and report rate

  • DPI: slider and quick presets (400, 800, 1600, 3200).
  • Report rate: how often the device reports to the computer. Devices with onboard profiles only allow changing it in host mode (see Profiles).
  • SmartShift: ratchet or free-spinning wheel, with a threshold for automatic switching.
  • Wheel: Smooth (high-resolution) scrolling and Invert scrolling direction.
  • Thumb wheel (mice that have one): Invert thumb wheel direction and what it does. Horizontal scroll (system) leaves it to the operating system; the other modes (horizontal scroll by pyLogi, zoom with Ctrl, volume, switch tabs) are performed by pyLogi, which must be running. Written from the documented protocol; not yet verified on real hardware.

Onboard profiles

Gaming devices store profiles in their own memory, so they work on any computer. This section reads and edits them.

  • Use onboard profiles: on = the device uses its stored profile; off = host mode, where the computer controls settings such as the report rate.
  • Which profile the device uses. The Profile list chooses the profile you are editing; the one marked ● is the profile the device is using right now. To change it, select another profile and press Use this profile (only in onboard mode). The choice is stored in the device, so it survives switching it off and moving it to another computer.
  • Choose a profile, then edit its name, colour, report rate, the five DPI levels, the default and shift DPI levels, and each button's binding (mouse button, key with modifiers, media key, special function, or disabled).
  • Save to device writes the profile. A backup of all profiles is saved first and a CRC is recalculated, as the device requires. Reload discards edits. Export… and Import… use a JSON file.

Lighting

  • Key layout and Key size: the map shows only the keys your keyboard has. pyLogi reads them from the keyboard itself (it reports which keys exist: a TKL has no numpad keys, an ISO keyboard has the extra <> key), so Automatic normally just works. If a model reports nothing, choose ANSI/ISO and Full size/TKL by hand; then every key of that layout is drawn. The legends are the US ones.
  • Click keys to select them (drag to select several, Ctrl-click to toggle). Pick a colour, then Apply to selected or Apply to all. Rainbow paints a gradient and Select all selects every key.
  • Copy colour from a key (or right-click a key): the key's colour becomes the picker colour, ready to apply to other keys.
  • Load colour from profile… reads the fixed colour stored in an onboard profile and applies it to all keys (profiles using a lighting effect cannot be loaded).
  • Reset colours forgets the per-key colours pyLogi re-sends and returns the keyboard to the lighting stored in its active profile.
  • Save colour to profile… writes the picker colour as the fixed lighting colour of an onboard profile, kept in the keyboard's memory. Individual per-key colours are not stored in profiles (they stay software-controlled and are re-sent on reconnect).
  • Save preset… and Load preset… store colour maps as JSON files.
  • Effect: besides static colours, pyLogi can animate the keys: Wave and Breathing and Radar and Starlight use the colour you picked; Rainbow wave and Colour cycle use the whole spectrum; Ripple on key press and Reactive light the keys you press. Choose one, set the Speed and press Play effect; speed and colour can be changed while it plays. The effects are drawn by pyLogi (key by key), so it has to keep running, and the effect starts again when the keyboard reconnects. Applying a static colour, or Stop effect, ends it. The two key-press effects read the key codes of your keyboard from /dev/input, which needs your user to be in the input group; only the key code is used, to light that key, and nothing is stored. On a slow link (a receiver) the animation is less smooth.
  • Zones: a colour for each lighting zone. Backlight: on/off and level for keyboards that have one.

Key colours are sent live and remembered by pyLogi, which sends them again whenever the keyboard reconnects. They are not saved inside the keyboard.

Webcams

The left card shows a live preview; the camera is opened only while this page is visible, and is released when you leave it. If another program is using the camera you will be told.

The right card has the controls the camera driver provides:

  • Lens: zoom, pan, tilt, focus and exposure. Focus and exposure have an Auto chip; while Auto is on the slider is greyed out because the camera controls the value.
  • Image: anti-flicker (50/60 Hz), backlight compensation, brightness, contrast, saturation, sharpness, gain and white balance (with Auto).
  • Presets: Default (the camera's factory values), Streaming, Video call and your own. + New saves the current values under a name; right-click a preset for Update with the current values, Rename… or Delete; on the built-in ones, Customise with the current values (marked with *) and Restore the original. Reset to defaults restores the factory values.
  • Video format: pixel format (MJPG, YUYV, H264…), size and frame rate. Applying it pauses the preview. Programs that choose their own format override it.
  • Auto-adjust and lock: lets the camera pick exposure, focus and white balance for a moment, then keeps those values as manual ones.
  • Presets by application…: a preset that switches on while an application has the focus (for example Video call for zoom) and gives way to the previous one afterwards. It uses the same window detection as the application profiles of mice.
  • Grid, Mirror and Histogram under the preview are viewing aids only; they do not change the camera. Some drivers add action buttons (such as Pan/Tilt Reset), shown with a Run chip.
  • Every change is remembered and written again when the camera is plugged in or the computer wakes up. A camera is recognised by its serial number or, without one, by the USB port it is in. The tray menu lists the presets of each camera, and --set accepts preset=NAME and video-mode=MJPG:1280x720@30.

The Device section

  • Device details: name, category, state, battery (with a 7-day chart), connection, device key (the identifier under which pyLogi stores its settings) and serial number.
  • Easy-Switch: the computers the device is paired with. Switch host moves the device to another computer (it disconnects from this one). Rename… changes the name stored in the device.
  • Keys (keyboards): Fn lock, when the keyboard supports it.
  • Configuration: Device picture lets you choose your own image for this device (it becomes its default picture everywhere) or go back to the original one. Manage this device keeps pyLogi's settings applied; turning it off restores the original button functions and stops applying anything. Also: counters of what is stored, Settings, Configuration folder and Remove device….

Adding and removing devices

Receivers (button in the header) shows a tree with every receiver found — family, product ID, serial, port, slots — and, under it, the devices connected to it with their type, battery, serial, unit ID and protocol. Refresh rereads the list.

Add lists your receivers. For Unifying, LIGHTSPEED and Nano receivers, Pair new device opens pairing for 30 seconds: switch the new device on or press its connect button. Unpair asks which paired device to remove and confirms; the new device is reported as soon as it connects. Bluetooth devices are paired in the system's Bluetooth settings (Bluetooth settings… opens them). For Bolt receivers, Pair new device searches for devices in pairing mode (hold the Easy-Switch button for three seconds until the LED blinks quickly) and then shows the passkey to type on the keyboard or the left / right clicks to make on the mouse. This flow has been written from the documented protocol and may need adjustments on some devices; if it fails, use the system's Bluetooth settings.

Remove… offers:

Unpair from the receiverRemoves the device from its receiver. Needs confirmation; a backup is taken first. The device must be paired again to be used.
Remove the Bluetooth pairingRemoves it from the computer's Bluetooth devices (BlueZ). Needs confirmation.
Forget pyLogi settingsDeletes the stored buttons, profiles, colours and other settings of the device.
Hide from the listOnly hides it. Settings → Hidden devices → Show all brings it back.
Delete from pyLogiWipes everything stored about it (settings, battery history, picture, cached name) and never lists it again, not even among the hidden ones. Needs confirmation. Undo only with pylogi --restore-deleted (the settings stay deleted).

Settings

The settings are grouped in tabs: General, Start-up and tray, Notifications and Advanced. Hover any option for a short explanation.

  • Language: Automatic or one of the installed languages. Add your own by dropping a <code>.json file in the locales folder of the configuration folder.
  • Appearance: System (follows the OS, live), Light or Dark. Theme: Default, Midnight, Graphite, Forest, Sunset, Violet, Rose or your own JSON file in the themes folder. Forest, Sunset, Violet and Rose also change the accent colour.
  • Show product photos: downloads photos from the OpenLogi asset mirror on demand and caches them. Only the files of your devices' models are requested; nothing about you is sent. Off = drawn icons only. Photos are Logitech's property.
  • Start pyLogi with the desktop session: starts minimised to the tray.
  • Run in the background as a service (systemd) (Linux): installs a systemd user service (--service on) that starts pyLogi minimised with the graphical session and restarts it if it stops, so diverted buttons, macros and application profiles work with the window closed. It replaces the previous switch.
  • Show pyLogi in the application menu: adds or removes the launcher (entry and icon) in the user's application menu; no root needed. On Linux it also lets the dock show the pyLogi icon.
  • GNOME helper extension (only on GNOME): installs or removes the extension that tells pyLogi which application has the focus, needed for per-application profiles on Wayland. After installing it, log out and in again.
  • Tray menu: each online device with onboard profiles or Easy-Switch hosts has a submenu to change its active profile or host. Save compatibility report… writes a read-only file with the devices and features found (no serial numbers) that you can attach to a bug report; the same report is available as pylogi --report.
  • Keep running in the tray when closed: closing the window keeps pyLogi alive so software actions keep working.
  • Show the start-up screen: the splash screen with the logo while the devices are detected. Off = the window simply appears when ready (--no-splash does the same for one run).
  • Start hidden in the tray: no window or splash at start-up; use the tray icon to show it. If there is no tray, the window is shown anyway.
  • Monochrome tray icon: a single-colour glyph that blends in with the desktop's panel.
  • Remember window size and position: off = the window always opens at 1200×800.
  • Notify when the battery is low: one notification when a device falls to the chosen level (5–50 %) and an urgent one at the second level. They re-arm once the battery has recovered or the device charges.
  • Notify when a device connects or disconnects: a notification each time a device goes offline or comes back.
  • One instance: launching pyLogi again shows the running window instead of starting a second copy. pylogi --toggle shows or hides it, handy for a keyboard shortcut.
  • Battery history (Device page): the last 30 days with a value axis; hover to read the level and date. When there is enough data it also shows an estimate of the days left.
  • Record a debug log: writes debug.log in the configuration folder with the system, the HID interfaces, the devices found (a new table whenever the list changes), connect / disconnect and lost-ping events, merged duplicates, errors and crashes. Use it when a device is missing, listed twice or flickers, and attach the file to a bug report. Serial numbers, unit ids, Bluetooth addresses and your home folder are masked. Include the raw HID++ traffic also records every report in debug-hid.log (large). pylogi --debug-log records one run only.
  • Export settings… / Import settings…: move the whole configuration between computers.
  • Hidden devices and Show all.

Command line

Run pylogi without options for the graphical interface. Options:

Settings for --set (name=value; booleans also accept toggle): dpi, smartshift (ratchet/free), wheel-invert and wheel-hires (on/off), report-rate (for example "2 ms"), fn-lock (on/off), thumb-invert (on/off), backlight (0–N) and camera.<control> (for example camera.brightness=140). DEVICE is any part of the device name or key.

pylogi --list --json
pylogi --get "MX Anywhere"
pylogi --set "MX Anywhere" dpi=1600 wheel-invert=on
pylogi --backup

Exit status is non-zero when something fails.

Where things are stored

Configuration folder (Linux: ~/.config/pylogi):

  • config.json: preferences. devices/: one settings file per device, named after it (for example G915_TKL__serial_abc.json); you can copy or delete one to move or reset a single device. known_devices.json: names remembered for offline devices. battery.json: battery history (30 days).
  • backups/: full snapshots taken before risky operations. Snapshots you take yourself are never deleted automatically; the auto-* ones made before each write to a device's memory keep only the newest 20 per device.
  • pictures/: images you chose. locales/ and themes/: your own languages and themes.

Photo cache (Linux: ~/.cache/pylogi/images) can be deleted at any time.

Safety and backups

  • pyLogi saves a backup before anything that can destroy data on a device (writing onboard profiles, unpairing, the self-test).
  • pylogi --backup snapshots every detected device on demand.
  • pylogi --self-test writes a temporary value to each setting, reads it back, restores it and checks the device ended identical to its backup.
  • pylogi --trace-hid FILE logs every HID++ report, for bug reports.
  • Switching a device to another computer (Easy-Switch) was not tested on real hardware because it would leave the device on the other computer.

Troubleshooting

  • No devices / "permission denied" (Linux). Install the udev rules and re-plug the devices: sudo cp packaging/42-pylogi.rules /etc/udev/rules.d/ && sudo udevadm control --reload && sudo udevadm trigger.
  • A wireless device is Offline. It is asleep. Move it or press a key.
  • Buttons or settings change back. Another manager is running (see the yellow banner). Close it.
  • Software actions do nothing. pyLogi must be running, the button must be set to an action, and on Linux /dev/uinput must be writable (the udev rules grant it). About → System shows the status.
  • Application profiles never switch. On GNOME/Wayland install the helper extension and log in again; on Sway, Hyprland, Niri and KDE (with kdotool installed) it works out of the box; on other Wayland desktops only XWayland windows are detected.
  • Report rate is refused. Turn off Use onboard profiles first (host mode).
  • No camera preview. Another program is using the camera, or Qt Multimedia has no backend.
  • No photos. Enable them in Settings; they need an internet connection the first time. A drawn icon is used otherwise.
  • Reporting a problem. Copy About → System and attach a --trace-hid log.
